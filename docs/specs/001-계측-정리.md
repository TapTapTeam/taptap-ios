# 001. 계측 정리

- 상태: 초안
- 목표 버전: 1.2.4
- 릴리스 주: 2026-11-23

## 문제

지금 수치로는 세 가지를 답할 수 없다. 코드는 2026-11-23 `develop` 기준이다.

1. **실사용자가 몇 명인가.** 디버그 빌드의 이벤트가 운영 분석 프로젝트로 들어간다. `AnalyticsConfiguration.fromMainBundle`에서 `DEBUG` 여부는 `isDebugLoggingEnabled`에만 쓰이고, `AnalyticsService.init`은 키가 있으면 GA4, Amplitude, Mixpanel 프로바이더를 그대로 붙인다.
2. **확장을 실제로 켠 사람이 몇 명인가.** 온보딩의 Safari 설정 안내를 본 것(`onboarding_step_view`, `step_name=safari_setting`)은 잡히지만 확장 스크립트가 페이지에서 실행됐다는 이벤트가 없다. iOS에는 앱에서 확장 활성 여부를 묻는 API가 없어 스크립트 쪽에서 알려야 한다. 지금 가장 이른 신호는 첫 `highlight_created`인데, 확장을 켜고도 하이라이트를 못 만든 사람은 여기서 빠진다.
3. **더블탭 문장 선택이 얼마나 실패하는가.** 실패 경로가 모두 조용히 끝난다.
   - `sentence.js`의 `selectSentenceAt`: `caretRangeFromPoint`가 범위를 못 주거나 텍스트 노드가 아니면 아무 일도 일어나지 않는다.
   - 같은 함수가 문장 경계를 텍스트 노드 하나 안에서만 찾는다. 링크나 강조가 섞인 문장은 노드 경계에서 잘린다.
   - `gesture.js`의 `handleTouchEnd`: 300ms 안에 `touchend`가 두 번 오면 손가락이 움직였는지와 상관없이 더블탭으로 본다. 빠른 스크롤도 문장 선택을 부를 수 있다.

3번은 다음 릴리스(002, 문장 하이라이트 수정)에서 고친다. 이번에는 고치기 전 기준선을 만든다.

## 바꿀 것

- 디버그 빌드로 실행하면 이벤트가 콘솔에만 찍히고 GA4, Amplitude, Mixpanel로는 나가지 않는다.
- 확장 스크립트가 어떤 페이지에서든 처음 초기화되면 `extension_activated`를 한 번 보낸다.
- 더블탭으로 문장 선택을 시도하면 결과와 함께 `sentence_select_attempted`를 보낸다.
- 앱이 `extension_activated`를 전달할 때 사용자 속성 `has_activated_extension`을 `true`로 둔다.

문장 선택과 하이라이트의 동작 자체는 그대로다.

## 하지 않을 것

- 문장 선택 로직 수정. 002에서 한다.
- 페이지 주소나 호스트 이름 전송. 사용자가 읽는 사이트의 기록이 되고 App Store 개인정보 선언을 바꿔야 한다. 실패가 많은 사이트는 재현 페이지로 찾는다.
- 이미 쌓인 데이터의 정정. 지난 기간은 분석 도구에서 기간과 코호트로 걸러 본다.
- 앱을 열지 않는 사용자의 확장 이벤트 전송. 확장 이벤트는 지금처럼 앱이 열릴 때만 나간다.
- `ExtensionAnalyticsQueue`의 프로세스 간 원자성 보강.
- macOS 앱 계측.

## 완료 조건

- [ ] Debug 구성으로 시뮬레이터에서 실행하면 로그에 `분석 프로바이더 시작: Console`만 나온다. (`log stream`으로 확인)
- [ ] Release 구성 빌드에서는 키가 있는 프로바이더가 모두 시작된다. (같은 로그 줄 확인)
- [ ] 원격 전송이 꺼진 구성에서는 키가 있어도 원격 프로바이더가 붙지 않는다. (`AnalyticsKit` 테스트 추가, 전체 통과)
- [ ] 확장이 처음 실행된 페이지에서 `extension_activated`가 1건 나가고, 같은 기기의 다음 페이지 로드에서는 나가지 않는다.
- [ ] 문장 위 더블탭은 `result=selected`, 글자가 없는 곳의 더블탭은 `result=no_text`로 나간다.
- [ ] 링크가 섞인 문장의 더블탭은 `boundary`가 `cut_start`, `cut_end`, `cut_both` 가운데 하나로 나간다.
- [ ] 손가락을 10px 넘게 움직인 두 번의 터치는 `is_moved=true`로 나간다.
- [ ] 한 페이지에서 6번째 시도부터, 하루 21번째 시도부터는 이벤트가 나가지 않는다.
- [ ] 새 이벤트의 속성에 주소, 호스트, 본문 글자가 없다. (전송 메시지 덤프 확인)
- [ ] 이미 있는 하이라이트를 더블탭하면 지금처럼 삭제 흐름으로 가고 시도 이벤트는 나가지 않는다.
- [ ] `TapTap`과 `TapTapMac` 빌드가 통과한다.

확장 항목은 검증용 HTML 페이지에 확장 스크립트를 싣고 가짜 `browser` 객체로 전송 메시지를 받아 확인한다. WebKit 자동화로 터치와 더블클릭을 재현한다.

## 설계

홍 확정 전이다.

### 디버그 전송 차단

- `AnalyticsConfiguration`에 `isRemoteDeliveryEnabled: Bool`을 더한다.
- `AnalyticsService.init(configuration:)`은 이 값이 `false`면 GA4, Amplitude, Mixpanel 프로바이더를 만들지 않는다. 콘솔 프로바이더는 지금처럼 `isDebugLoggingEnabled`를 따른다.
- `fromMainBundle`은 Release에서 `true`, Debug에서 `false`를 넣는다. Debug에서도 실행 인자 `-analyticsRemoteDelivery YES`가 있으면 `true`로 둔다. 프로바이더 연동을 시뮬레이터에서 확인할 때만 쓴다.
- 버린 대안: Debug에서 키를 비워 반환하기. 구성 값이 사실과 달라지고 실행 인자로 다시 켤 자리가 없다.

### 이벤트 계약

| 이벤트 | 보내는 곳 | 속성 | 횟수 |
|---|---|---|---|
| `extension_activated` | `bootstrap.js` 초기화가 끝난 뒤 | `surface` | 기기당 1회 |
| `sentence_select_attempted` | `gesture.js`의 `handleDoubleTap`에서 문장 선택 경로를 탄 뒤 | `surface`, `input`, `result`, `boundary`, `is_moved` | 페이지 로드당 5건, 하루 20건까지 |

| 속성 | 값 | 뜻 |
|---|---|---|
| `surface` | `safari_extension` | 기존 확장 이벤트와 같다 |
| `input` | `touch`, `mouse` | `touchend` 경로인지 `dblclick` 경로인지 |
| `result` | `selected`, `no_text` | 문장 범위를 잡아 툴팁을 띄웠는지 |
| `boundary` | `complete`, `cut_start`, `cut_end`, `cut_both`, `none` | 문장 끝 글자를 못 찾고 노드 경계에서 멈췄고, 같은 블록 안에 이어지는 글자가 있으면 그쪽을 `cut`으로 본다. `result=no_text`면 `none` |
| `is_moved` | `true`, `false` | 두 번의 터치 중 하나라도 `touchstart`에서 `touchend`까지 10px 넘게 움직였는지. 마우스는 `false` |

- 사용자 속성 `has_activated_extension`은 `AnalyticsUserProperty`에 케이스를 더하고, `AppDelegate.deliverPendingExtensionEvents`가 `has_highlighted`와 같은 방식으로 둔다.
- `ExtensionEvent.typedValue`의 Bool 키에 `is_moved`를 더한다.

### 상태가 사는 곳

- 활성화 전송 여부와 하루 시도 수는 `browser.storage.local`에 둔다. 페이지의 `localStorage`는 사이트마다 달라서 쓸 수 없다.
- 페이지 로드당 시도 수는 `TapTap.analytics` 안의 변수로 둔다.
- 버린 대안: 네이티브 핸들러에서 App Group 값으로 중복을 거르기. 페이지를 열 때마다 네이티브 메시지가 한 번씩 나간다.

### 모듈 경계

- `sentence.selectSentenceAt`은 `{ result, boundary }`를 돌려주고 계측을 모른다.
- `gesture.js`는 터치 이동 여부를 재서 `TapTap.analytics.trackSentenceSelectAttempted`를 한 곳에서 부른다. `touchstart` 리스너는 passive로 더하고 기존 판정에는 손대지 않는다.
- 상한과 중복 판단은 `analytics.js` 안에 둔다.

## 작업

1. `AnalyticsKit`: 원격 전송 여부를 구성에 더하고 테스트를 쓴다.
2. 확장: `extension_activated`.
3. 확장: `sentence_select_attempted`와 상한.
4. 앱: `has_activated_extension` 사용자 속성과 `is_moved` 타입 변환.
5. `AGENTS.md` 계측 절에 디버그 전송 규칙 한 줄을 더한다.
6. 버전 1.2.4와 릴리스 노트.

## 홍이 확인할 것

- 실기기 Safari에서 글 세 개에 더블탭해 하이라이트 만들기와 지우기가 지금과 같은지.
- TestFlight 빌드로 위 동작을 한 뒤 앱을 열어 Amplitude에 `extension_activated`와 `sentence_select_attempted`가 들어오는지.
- App Store 개인정보 선언은 바꾸지 않는다. 새로 수집하는 데이터 유형이 없다.

## 출시 후 볼 수치

- 확장 활성 비율: 출시 뒤 `onboarding_complete` 사용자 가운데 `has_activated_extension=true`인 비율.
- 문장 선택 실패율: `is_moved=false`인 시도 가운데 `result=no_text`이거나 `boundary`가 `cut`인 비율.
- 오탐 비율: 전체 시도 가운데 `is_moved=true`인 비율.

002를 시작할 때 그때까지 모인 시도 수를 함께 적는다. 30건이 안 되면 비율로 판정하지 않고 실패 유형의 건수와 재현 페이지로 수정 범위를 정한다.
